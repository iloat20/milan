> **版本**: v2.0 | **日期**: 2026-08-13 | **状态**: 设计定稿 → 生图

## 0. 设计哲学（基线约束）

### 0.1 命题
**「山海经 × 现代卡牌标杆」** — 在原神/崩坏/绝区零/明日方舟/少女前线等中文卡牌市场主流的基础上，保留东方神话的精神内核。

每个角色是**「神话原型（视觉锚点）+ 现代卡牌美学（构图与质感）」** 的融合体：
- 神话原型来自 `data.json` 的 `Lore/Story/Title/Weapon`，决定"画什么"
- 现代卡牌美学来自本规范，决定"怎么画"

### 0.2 三条铁律
1. **识别优先于美化**：辨识度是卡牌的第一价值。若一个角色在 0.5 秒内被认错身份，无论多美都是失败品。
2. **全身入画优先于头部特写**：半身像会丢失装备、武器、姿势信息。UR 可微低视角仰拍，但脚必须入画。
3. **透明背景优先于纯色场景**：立绘的"场景"由 UI 层（详情页背景、抽卡演出）按需叠加，立绘本体只承担"角色 + 脚下氛围圈"。

## 1. 画布与格式

### 1.1 画布规格

| 稀有度 | 画布尺寸 | 比例 | 输出格式 | 透明 | 体积上限 |
|--------|----------|------|----------|------|----------|
| **UR** | 1536×2304 px | 2:3 | PNG-24 + Alpha | 强制 | 6 MB |
| **SSR** | 1280×1920 px | 2:3 | PNG-24 + Alpha | 强制 | 4 MB |
| **SR** | 1024×1536 px | 2:3 | PNG-24 + Alpha | 强制 | 3 MB |
| **R** | 832×1248 px | 2:3 | PNG-24 + Alpha | 强制 | 2 MB |

> **不沿用现状**：现有 1024×1536（UR/SSR）与 832×1186（R/SR）分辨率不统一且偏低，UR 文件仅 45-80KB 表明已经过度有损压缩。v2 阶梯式提分，UR 是现状的 2.25 倍像素。
>
> **透明背景为何重要**：当前所有立绘均为 VP8 无 alpha 通道，叠在详情页背景上会出现"切豆腐块"感。透明背景允许程序在角色脚下叠加阵营色氛围光、抽卡裂隙特效、突破动画等图层，无需重新抠图。

### 1.2 安全区

```
┌──────────────────────────┐
│  ▲ 顶部 8% 安全留白       │  ← 头发不触顶
│                          │
│      [头部 23%]          │
│                          │
│      [躯干 38%]          │
│                          │
│      [腿部 26%]          │
│                          │
│  ▼ 底部 5% 氛围光圈      │  ← 脚下浮空光晕
└──────────────────────────┘
```

- 头顶留白 8%（防止 UI 顶栏遮挡）
- 脚底留白 5%（容纳"脚下氛围圈"层）
- 左右各留 3%（容纳特效溢光）
- 武器/特效可超出安全区 ≤10%

### 1.3 命名与目录
- 源文件：`docs/superpowers/art-direction/portraits-v2/source/<rarity>_<pinyin>.png`
- 透明版：`MilanKotlin/app/src/main/res/drawable-nodpi/char_<rarity>_<pinyin>.webp`（无损 WebP VP8L + Alpha）
- 缩略图：`MilanKotlin/app/src/main/res/drawable-nodpi/char_<rarity>_<pinyin>_thumb.webp`（256×384）

## 2. 构图系统

### 2.1 三段式分镜（参考绝区零/原神角色 PV 静态帧）

每张立绘沿垂直方向划分三个叙事区段：

| 区段 | 占比 | 职责 | 典型元素 |
|------|------|------|----------|
| **上段**（头部以上） | 25% | 世界观氛围、阵营符号、能量背景 | 阵营徽记、能量光环、星云 |
| **中段**（面部+胸部） | 35% | 角色灵魂、情绪 | 面部表情、胸口徽记、武器主刃 |
| **下段**（腰+脚） | 40% | 动态动作、装备细节 | 衣摆弧线、武器握持、足部环境 |

> **常见错误**：v1 设计稿把所有细节堆在中段（胸部+头部），上段空白、下段截断。新规范强制三段都有内容，下段占比最大以强化"动态"。

### 2.2 视线引导

- **主光源方向统一**：7 点钟方位（左上方 45°）—— 已是 v1 规范，v2 强化
- **补光方向**：2 点钟方位（右上方 30°）—— 使用阵营色作为色温
- **轮廓光**：角色背后下方 5 点钟，使用稀有度色（金/紫/蓝/白）
- **角色视线**：除"闭目/斜视"特定立意外，**主视线应斜向上 15°** —— 这是现代卡牌让角色"有精气神"的潜意识技巧
- **观者视线流向**：从左下（脚部战斗姿态）→ 中部（武器）→ 右上（面部/能量爆炸）

### 2.3 动态姿态库（直接套用）

| 姿态编号 | 名称 | 适用角色类型 | 关键参数 |
|----------|------|--------------|----------|
| **P1** | 神祇凌空 | UR 神/创世级 | 全身悬浮，衣摆向上飘，头部仰视 20° |
| **P2** | 战阵冲锋 | UR/SSR 战士 | 身体前倾 30°，武器高举或前指，脚下爆裂圈 |
| **P3** | 法术咏唱 | UR/SSR 法师 | 双臂张开，掌心相对或向天，法阵在脚下 |
| **P4** | 高速冲刺 | SSR/SR 速度型 | 身体水平前倾 45°，速度线/风刃包裹 |
| **P5** | 防御姿态 | SR/R 守护型 | 盾牌在前，身体侧立，重心下沉 |
| **P6** | 蹲伏潜行 | SR/R 敏捷型 | 膝盖弯曲，重心下压 30° |
| **P7** | 祈祷/治愈 | SR/R 辅助型 | 双手合十或托举物体，微微低头 |
| **P8** | 咆哮震慑 | R/SR 兽化型 | 双臂张开，胸部前挺，嘴部张开 |

> 每个角色必须在 v2 角色稿中标注**主姿态编号**与**2 个修饰参数**（如"P2 + 头部低俯 10° + 右手向后拉弓"）。

### 2.4 头身比（参考现代卡牌惯例）

| 稀有度 | 头身比 | 说明 |
|--------|--------|------|
| UR | 7~8 头身 | 修长、神性化、idol 比例 |
| SSR | 6~7 头身 | 标准、力量感 |
| SR | 5~6 头身 | 略萌、亲切感 |
| R | 4~5 头身 | 萌系、Q 版化（仅对兽形/小孩角色） |

> 兽形角色（饕餮、狻猊）不受头身比约束，按生物解剖学处理。

## 3. 视觉识别锚点（铁律 — 每个角色必选 3 项）

**这是本版本与 v1 的最大差异。** v1 描述过细但缺乏"硬约束"，导致 SR 狻猊设计为"狮面人身"但实图是"野猪穿臂铠"。

每个角色在 v2 角色稿中必须列出**3 个识别锚点**（Anchor），并在生图 Prompt 的 `key_elements` 段强制包含：

| 锚点类型 | 含义 | 示例（烛龙） |
|----------|------|--------------|
| **A. 神话原型标志** | 山海经/神话原文中不可改的视觉签名 | 人面蛇身（关键：必须保留蛇尾） |
| **B. 武器/道具** | 角色标志性的"道具指纹" | 阖辟神瞳·昼夜轮（金黑双面圆轮） |
| **C. 身体特征** | 区别于他人的硬性解剖/纹身特征 | 异色瞳（左金右银） |
| **D. 服饰标志** | 标志性服饰单品 | 龙首肩甲（左右各一） |
| **E. 行为/姿态** | 标志性动作或表情 | 睁眼瞬间（背景日/夜分立） |

> 3 个锚点必须**全部出现**才视为合格品。生图后由 QC 阶段逐项核对。

## 4. 配色系统（双层叠加）

每张立绘的色彩由**5 套色板叠加**决定（顺序为优先级）：

### 4.1 阵营色（决定基底情绪）

| 阵营 | 主色 | 辅色 | 强调色 | 适用 |
|------|------|------|--------|------|
| **Shinwa 神話** | 暗紫金 `#9A6BFF` | 朱砂红 `#E34234` | 青古铜 `#1FB6A6` | 烛龙/桔梗/凤凰/飞廉/狻猊/旋龟/狸力/蠃鱼/饕餮 |
| **Aether 以太** | 暮紫 `#C79BFF` | 霓虹青 `#00E5FF` | 星银 `#E8E2F2` | 虚无/刻晴/商羊/精卫/毕方/女娲/钦原/当康/花妖/夜叉 |
| **Ironveil 铁帷** | 冷钢灰 `#7A8A9A` | 电弧蓝 `#4A90D9` | 锈橙 `#C96A2E` | 刑天/雷神/蚩尤/白虎/穷奇/跂踵/山魈 |

### 4.2 稀有度色（决定特效高光与稀有度光环）

| 稀有度 | 稀有度色 | 出现位置 |
|--------|----------|----------|
| UR | 熔金 `#FFC857` | 角色身后全屏光晕、武器符文、稀有度边框 |
| SSR | 暮紫 `#C79BFF` | 脚下光圈、武器刃光、星级 |
| SR | 霜蓝 `#7FC4FF` | 装备边缘、能量线、星点 |
| R | 苍白 `#E8E2F2` | 微光、点状高光 |

> 重要：**稀有度色不能盖过阵营色与元素色**。它只作为"高光层"出现，不应大面积铺底。

### 4.3 元素色（8 元素统一调色板，2026-08-11 定稿）

| 元素 | 主色 | 辅色 | 视觉特征 |
|------|------|------|----------|
| **Flame 火** | 熔岩橙 `#FF4D00` | 金黄 `#FFD700` | 飘忽羽翼、爆炸光斑 |
| **Wood 木** | 翡翠绿 `#2E8B57` | 嫩芽 `#B9F6CA` | 藤蔓、叶片、生长粒子 |
| **Water 水** | 深海青 `#0097A7` | 霜白 `#B2EBF2` | 流体、气泡、光线折射 |
| **Earth 土** | 大地褐 `#795548` | 赭石 `#8B4513` | 碎岩、晶簇、藤根 |
| **Metal 金** | 枪铁灰 `#4A4A5A` | 紫铜 `#B87333` | 刀刃、齿轮、铆钉 |
| **Light 光** | 神圣金 `#FFD600` | 珍珠白 `#FFFAF0` | 光柱、光球、星屑 |
| **Shadow 暗** | 暗紫黑 `#0D0221` | 毒绿 `#32CD32` | 黑雾、影子触手、瞳孔 |
| **Thunder 雷** | 雷电金 `#FFD600` | 电光蓝 `#00BFFF` | 电弧、闪电、静电场 |

### 4.4 角色情绪色（点缀，1-2% 占比）

用于眼神、嘴角、配饰的局部高饱和强调色，由角色性格决定：
- 神圣 → 纯白
- 疯狂 → 血红
- 神秘 → 钴蓝
- 慈悲 → 暖粉
- 暴烈 → 锈红

### 4.5 配色优先级

```
底层氛围（40%）> 阵营色（25%）> 元素色（20%）> 稀有度色（10%）> 情绪色点缀（1-2%）
```

底层氛围由背景渐变承担；阵营色出现在服装主色；元素色出现在武器与特效；稀有度色出现在稀有度光环与边框；情绪色点睛。

## 5. 光影系统（统一光配方）

### 5.1 三点布光

| 灯光 | 方向 | 强度 | 色温 | 用途 |
|------|------|------|------|------|
| **主光** | 左上方 7 点钟 45° | 100% | 中性白 `#FFF8E7` | 角色轮廓、明暗交界 |
| **补光** | 右上方 2 点钟 30° | 30% | 阵营色 | 阴影染色、环境反射 |
| **轮廓光** | 背后下方 5 点钟 | 50% | 稀有度色 | 角色边缘发光、与背景分离 |

### 5.2 阴影规则
- 硬阴影边缘 = 戏剧性（UR/SSR 默认）
- 软阴影边缘 = 柔和（SR/R 默认）
- 阴影内必须使用补光的"色染"（环境光遮蔽的色彩溢出），不要纯黑

### 5.3 高光与发光
- 武器刃光：使用元素主色 + 15% 白色高光
- 眼睛高光：双高光点（左上 + 右上），使用主光色
- 金属/湿润表面：尖锐镜面反射（高光直径 < 5px）
- 皮肤/布料：柔和漫反射（高光呈羽化圆形）

## 6. 透明背景处理要点

### 6.1 输出规范
- **格式**：PNG-24 + Alpha 8-bit 通道
- **位深**：8-bit/通道（不要 16-bit，会被 Android BitmapFactory 丢弃）
- **压缩**：开发期 PNG，生产期转 WebP VP8L Lossless + Alpha

### 6.2 抠图边缘
- 头发丝/衣摆飘带等细部：保留 ≤2px 的羽化（避免"硬切"感）
- 武器/道具边缘：硬切（保留锐度）
- 脚下/地面：不包含地面元素，**脚下氛围圈**单独由 UI 层绘制

### 6.3 透明区域
- 角色轮廓外 5px 内可保留轻微的环境色溢染（来自主光的漫反射）
- 角色轮廓外 5px 外必须完全透明（Alpha = 0）
- 透明背景中**禁止**出现以下"硬黑底"：
  - 纯黑矩形（最常见错误，会让角色在浅色 UI 上像贴纸）
  - 同色系的环境光（破坏可叠加性）
  - 模糊的渐变光斑（细节页背景会重复）

### 6.4 通道检查命令

```bash
# 用 ImageMagick 验证透明通道
magick identify -verbose char_ur_zhulong.png | grep -A1 "Channel"

# 用 ffmpeg 验证透明背景
ffmpeg -i char_ur_zhulong.png -vf "alphaextract" -f null -

# 批量检查全 28 张
for f in char_*.webp; do
  alpha=$(ffprobe -v error -select_streams v -show_entries stream=pix_fmt -of default=nw=1 "$f" | grep -o 'yuva\|rgba')
  echo "$f: $alpha"
done
```

> 当前全部 28 张文件均为 VP8 无 alpha 通道，全部需要重新生图。

## 7. 生图参数基线

### 7.1 模型选择优先级

| 优先级 | 模型 | 适用 | 备注 |
|--------|------|------|------|
| 1 | Flux 1.1 Pro | UR/SSR | 角色细节最细腻，背景光晕最自然 |
| 2 | Midjourney v7 | SSR/SR | 风格化强，姿势可控性好 |
| 3 | SDXL 1.0 + Juggernaut XL | SR/R | 性价比高，参数可控 |

### 7.2 通用参数（SDXL 基准）

```
正采样:
  sampler: DPM++ 2M Karras
  steps: 40
  cfg_scale: 7.5
  size: 见 §1.1 画布规格
  model: juggernautXL_v9 或等价

负采样 (negative_prompt):
  "cropped, close-up, half-body, bust, headshot, white background, 
   colored background, text, watermark, signature, frame, border,
   low quality, blurry, deformed hands, extra fingers, mutated,
   ugly, bad anatomy, bad proportions, cloned face, 
   3d render, photorealistic, nsfw, multiple characters"
```

### 7.3 Prompt 结构（5 段式）

每个角色 Prompt 严格按以下 5 段组织：

```
[1. 主体描述] Full-body character portrait of [名字], [年龄/性别/体型].
              [2-3 句外形 + 服饰 + 识别锚点]
              
[2. 姿态]      Dynamic pose: [P编号 + 修饰参数]. 
              [衣摆/头发/特效的流向描述]
              
[3. 氛围]      Atmosphere: [环境元素 + 光照 + 情绪].
              Background: [透明背景标识 + 脚下氛围圈描述]
              
[4. 风格]      [世界风格] style: [渲染方式 + 线条 + 上色 + 质感 + 主色调].
              Lighting from upper left, [阵营色] rim light.
              High detail, gacha game character art, 2:3 aspect ratio,
              transparent background.
              
[5. 关键元素]  key_elements: [A 锚点] + [B 锚点] + [C 锚点]
```

### 7.4 后期处理流水线

```
1. 生图（512×768 seed 图，hires fix 2x）
2. Upscale（4x-UltraSharp 或 Flux SR）
3. 抠图（rembg / SAM / 人工精修）
4. 透明背景质检（§6.4 命令）
5. 边缘羽化（头发丝/衣摆 ≤2px 羽化）
6. 阵营色氛围光晕（脚下 200px 圆形径向渐变）
7. WebP 转换（cwebp -lossless -m 6 -alpha_q 100）
8. 缩略图生成（256×384，重采样）
9. 入库（按 §1.3 路径）
```

## 8. 质量验收（QC Checklist）

每张立绘入库前必须通过以下检查项：

### 8.1 构图
- [ ] 透明背景（Alpha 通道存在）
- [ ] 全身入画（头顶留白 5-10%，脚底留白 5%）
- [ ] 头身比符合稀有度
- [ ] 武器/道具完整可见
- [ ] 三段式分镜（上/中/下）都有内容

### 8.2 识别
- [ ] 3 个识别锚点全部出现
- [ ] 面部表情清晰可读
- [ ] 角色名称在 0.5 秒内可被认对
- [ ] 阵营符号（徽记/纹章）出现 ≥1 次
- [ ] 元素符号（武器/特效）出现 ≥1 次

### 8.3 配色
- [ ] 阵营色出现在服装/装备主色
- [ ] 元素色出现在武器/特效
- [ ] 稀有度色出现在光环/边框
- [ ] 配色不超过 5 套（避免彩虹污染）
- [ ] 高光/暗部不出现纯黑/纯白硬切

### 8.4 光影
- [ ] 主光源来自 7 点钟（左上方 45°）
- [ ] 补光使用阵营色染色阴影
- [ ] 轮廓光让角色与背景分离
- [ ] 视线斜向上 15°

### 8.5 技术
- [ ] 文件体积符合 §1.1 上限
