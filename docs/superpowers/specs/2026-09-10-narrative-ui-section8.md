## 1. 世界观：一句话讲清楚

### 1.1 产品一句话（对外 / 商店页 / 启动）

> **裂隙撕开三界，你在碎片间召唤英灵，把破碎的原初之环重新拼回世界。**

### 1.2 三句展开（新手 30 秒可读完）

1. 千年前「大崩解」把世界切成 **神話 / 以太 / 铁帷** 三块。
2. 每个角色体内都有 **本源血脉 + 异域共鸣**——旧神与新神话在同一个人身上醒来。
3. 你要做的：**抽卡聚英灵 → 养成觉醒 → 组队爬塔 → 对抗虚无**。

### 1.3 阵营一句话

| 阵营 | 一句话 | 信条 |
|------|--------|------|
| 神話 Shinwa | 旧日之焰——用秩序把山海万灵重新立起来 | 秩序 · 传承 · 天人合一 |
| 以太 Aether | 星界之环——把裂隙当门，研究命运、改写命运 | 自由 · 知识 · 命运可违 |
| 铁帷 Ironveil | 钢铸之心——神明不可靠，进化才救命 | 进化 · 实用 · 弱肉强食 |

### 1.4 核心冲突（剧情钩子）

- **烛龙 vs 虚无**：昼夜节律 vs 万物归无。
- **刻晴 vs 烛龙**：人定胜天 vs 神明回归。
- **铁帷内战**：兵主是进化终点，还是被奴役的武器？

## 3. 卡牌文案规范

### 3.1 长度预算

| 文案类型 | 预算 | 位置 |
|----------|------|------|
| 技能名 | ≤ 6 字 | 卡面 / 战斗气泡 |
| 技能描述 | ≤ 28 字（Active/Ultimate）、≤ 24 字（Passive） | 详情技能栏 |
| 题记 lore | 1–2 句，≤ 40 字 | 角色故事页金箔竖条 |
| 登场/胜利台 | ≤ 12 字 | 抽卡 reveal / 结算横幅 |

### 3.2 语气三条

1. **世界观绑定**：技能效果必须能从 lore 反推（烛龙=昼夜/火，刑天=断首/干戚，虚无=湮灭/抹消）。
2. **短、有梗、不尬**：宁可「饿了。你们都别跑。」不要「无尽的贪欲将吞噬一切」。
3. **阵营口吻**：神話偏文言意象，以太偏冷静术语，铁帷偏军事短促。

### 3.3 现状抽检与修正样例

现状技能描述多在 20–35 字，可用；个别超长（如青璃破魂之箭）需压。

| 角色 | 技能 | 现状描述 | 建议压缩 |
|------|------|----------|----------|
| 烛龙 | 烛照八荒 | 以烛龙真火焚烧全体敌人，造成巨额火焰伤害 | **真火燎原，敌阵尽焚**（效果由数值层表达） |
| 虚无 | 湮灭奇点 | 在敌阵制造黑洞，持续吸引并撕裂范围内所有目标 | **召来奇点，扯碎一切** |
| 刑天 | 干戚狂舞 | 挥舞巨斧横扫前方，造成范围伤害并击退 | **干戚横扫，退敌三步** |
| 青璃 | 破魂之箭 | 射出贯穿一切的破魔箭，对单体造成巨额真实伤害并封印其技能3秒 | **破魔一矢，真伤封技** |

> 落地：改 `data.json` 的 Skills.Description → 跑 `tools/generate_gamecontent.py` 再生成 `GameContent.kt`。**禁止手改 GameContent。**

### 3.4 角色题记（已有，保持）

题记走 `CharacterLore` + `InfoPanels` 金箔竖条；新增角色沿用「本源 / 执念 / 羁绊」三色小标结构（见 portrait story-card 规范）。

## 4. 战斗反馈（出牌 / 攻击 / 受伤 / 死亡 / 胜利）

> Milan 是 **全自动放置战斗**，无「出牌」操作。本节将「出牌」映射为 **技能释放演出**（Ultimate / Active 触发时刻）。

### 4.1 已有（保留）

| 反馈 | 实现 | 位置 |
|------|------|------|
| 伤害飘字（普伤/克制/击杀/MISS） | `DamageFloatingText`，180ms 间隔时间线 | `ui/components/DamageFloatingText.kt` |
| 结算分镜 | 遮罩→标题弹入→奖励滚动→粒子→按钮 | `ui/components/BattleResultOverlay.kt` |
| 胜利/失败触觉 | `BattleHapticEffect` Victory/Defeat | `ui/effects/` |
| 胜利金箔 / 失败灰烬粒子 | `BattleParticles` | 同上 |
| 战斗日志条目色 | 元素光 + 击杀朱砂 | `TowerScreen` / `StrategicBattleScreen` |

### 4.2 缺口与规格

| 时刻 | 规格 | 优先级 |
|------|------|--------|
| **出招 / 技能** | 攻击者头像轻 punch-in（scale 1→1.12→1，120ms）+ 元素色横扫光痕（200ms）+ 对应 SFX | P0 |
| **攻击命中** | 受击方 shake（±4px，3 帧）+ 伤害数字色分档（已有）+ 命中音 | P0 |
| **受伤（我方）** | 屏幕边缘红闪 80ms（alpha 0.15）+ 轻触觉 tick | P1 |
| **技能 / Ultimate** | 全屏元素色 vignette 300ms + 技能名气泡从攻击者飞出 + 重触觉 | P0 |
| **死亡** | 受击方灰化 desaturate + 下沉 12px + 透明淡出 400ms + 「†」标记 | P0 |
| **胜利** | 已有结算层；补：最后一击慢放 0.5× 仅影响飘字间隔（不改领域日志） | P1 |
| **失败** | 已有灰烬粒子；补：全屏去饱和 200ms 后再弹结算 | P2 |

### 4.3 实现约束

- **只动 `ui/`**：领域 `StrikeEvent` 日志结构不变；演出层按 `events` 时间线驱动。
- 动效减弱开关（设计语言 §7.6）生效时：技能 vignette / 慢放关闭，仅保留飘字与结算淡入。
- 性能：同屏 punch-in 实例 ≤ 3；粒子沿用池化。

## 5. 音效

### 5.1 资产约定（已落地）

```
assets/audio/sfx/<名称>.ogg   # SoundPool
```

### 5.3 接线点

| 时刻 | 调用 |
|------|------|
| 抽取 / 揭示 | 已在 `GachaViewModel` / `GachaScreen` |
| 战斗时间线每条 StrikeEvent 开始 | `MilanAudio.playSfx("battle_strike")`；技能/大招键按 `StrikeEvent` 类型或技能 power 档位 |
| 结算层出现 | `battle_victory` / `battle_defeat` |
| 角色阵亡事件 | `battle_death`（与死亡动画同步） |

音效开关：沿用设置页 `soundEnabled` → `MilanAudio.setSfxVolume`（冷启动已同步）。

### 5.4 资产制作建议

- 单条 ≤ 0.8s，44.1kHz mono/stereo OGG，响度对齐 `gacha_*`。
- **2026-09-10 占位落地**：7 条 `battle_*` 由 `tools/generate_battle_sfx.py`
  程序合成（22.05kHz mono PCM/WAVE，扩展名 `.ogg`；SoundPool 按数据嗅探可播）。
  正式 Ogg Vorbis 同名覆盖即可，无需改代码。
- 战斗 BGM 可选 `bgm/battle.ogg`，进塔/爬塔切换（P2）。

## 6. 新手引导：3 分钟教会核心循环

### 6.1 目标循环（玩家要会的四步）

```
抽卡聚人 → 上阵编队 → 打一场 → 养成再抽
```

### 6.2 时间预算（总 ≤ 180s）

| 段落 | 时长 | 内容 | 形式 |
|------|------|------|------|
| 0. 开场剧情 | 20s | 一句话世界观 + 烛龙/虚无对峙（复用 Story 1-1 精简版） | `DialogueScreen` 可跳过 |
| 1. 首次寻访 | 40s | 强制十连（保底）→ 演出 → 得到门面角色 | 高亮「寻访」Tab + 手型光圈 |
| 2. 编队 | 30s | 空态卡组页 → 拖/点 1 人上阵 | 高亮空槽 + 文案「把刚到手的英灵放上去」 |
| 3. 首战 | 50s | 剧情关/爬塔第 1 层，自动战斗播完整 | 高亮「开始」；结算讲奖励 |
| 4. 养成闭环 | 30s | 详情页升 1 级（免费或极低价）→ 提示「变强了，再去寻访」 | 高亮升级按钮 |
| 5. 收束 | 10s | 「裂隙还在扩张——去收集更多英灵吧」+ 关闭引导 | Toast/横幅 |

### 6.3 交互原则

- **可跳过**：任意段提供「跳过引导」；跳过后不再强制（存档位）。
- **不挡路**：高亮用遮罩挖洞 + 指针，不用全屏锁死（除十连动画中）。
- **幂等**：`SaveData` 新增 `tutorialFlags`（默认空，向后兼容）；完成步写位，重进不重复。
- **文案短**：每步提示 ≤ 20 字，口吻贴世界观（「裂隙送来的第一份力量」）。

### 6.4 技术落点

| 改动 | 层 |
|------|----|
| `TutorialSaveData` / flags（`@Serializable` 新字段带默认值） | `data/` |
| 步骤状态机（纯 Kotlin，可单测） | `core` 或 `domain` 建议 `services/TutorialService` 挂 GameService |
| 高亮遮罩 / 指针组件 | `ui/components/TutorialOverlay.kt` |
| 步骤触发（首抽完成 / 编队成功 / 首战胜利 / 首次升级） | 对应 Screen/VM 事件回调 |
| 跳过与完成落盘 | 事务范式，失败不卡死（引导可重入） |

### 6.5 与现有剧情关系

- Story 1-1…1-3 已有烛龙开场；引导段 0 **复用/精简**该对话，不另写大段文本。
- 引导完成后，主页空态引导（「去寻访」）仍保留作兜底。

## 9. 红线

- 不改 `StrikeEvent` / 战斗领域计算；演出只读日志。
- 不手改 `GameContent.kt`；文案走 data.json + 生成器。
- 新存档字段必须带默认值；禁止改既有 `@SerialName`。
- 音频与引导 UI 失败静默/可跳过，不阻断核心循环。
