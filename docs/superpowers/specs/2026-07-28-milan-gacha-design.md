# Milan — 抽卡游戏设计文档

> 版本：v1.0 · 日期：2026-07-28 · 状态：待审阅

## 1. 概述

**Milan** 是一款面向 Android 平台的原创 IP 抽卡养成手游，采用 Unity 开发。核心循环是 **召唤（抽卡）→ 收集 → 养成 → 检视 → 战斗**，融合了多世界叙事、角色背景驱动的天赋养成、全自动放置战斗，以及 360° 交互式角色检视体验。

### 1.1 设计决策摘要

| 维度 | 决策 |
|------|------|
| 商业模式 | 原创 IP + F2P（抽卡内购 + 赛季票 + 可选广告） |
| 平台 | 仅 Android，Unity 引擎 |
| 战斗 | 全自动放置战斗 |
| 后端 | 先单机，架构预留后续联网扩展 |
| 角色成长 | 星级阶段 + 天赋分支；终极角色可「终极突破」突破等级上限 |
| MVP 范围 | 核心循环最小集（抽卡 + 养成 + 战斗 + 3D 检视） |
| 抽卡演出风格 | 次元裂缝 / 传送门（角色从不同世界穿越而来） |
| 整体美术风格 | 混合渲染（不同世界/角色适配卡通或写实画风） |
| MVP 角色数量 | 3–5 个角色，每个 2–3 阶段 |
| 3D 检视 | 360° 自由检视 + 交互反馈（动作 / 语音） |

### 1.2 核心愿景

打造一个「叙事驱动养成」的抽卡游戏：每个角色有自己的出身世界、背景故事和人际关系，天赋树由背景故事定制，养成过程伴随可视变化，满级满天赋展现华丽终极形态，最稀有的终极角色还能突破到最炫酷的终极突破形态。

## 2. 世界观与叙事系统

### 2.1 多世界架构

游戏世界由多个「次元/世界」构成，每个世界有独立的视觉风格和角色群：

| 世界 | 风格基调 | 代表角色类型 |
|------|---------|-------------|
| 和忍（Shinwa） | 东方忍者奇幻 | 忍者、武士、妖怪 |
| 星灵（Aether） | 宇宙能量科幻 | 星使、能量体、虚空行者 |
| 铁帷（Ironveil） | 赛博科技 | 仿生人、机甲、黑客 |

> MVP 先做一个世界，架构支持后续扩展新世界（新画风角色）。

### 2.2 角色背景与关系网

每个角色配有 `CharacterLore`：起源、性格、动机、出身世界，以及与其他角色的关系。关系类型包括：

- **宿敌 (Rival)** — 对立背景
- **战友 (Ally)** — 共同经历某事件
- **造物 (Creator / Creation)** — 创造者与被造物
- **跨世界羁绊** — 不同世界角色因事件产生联系

### 2.3 关系的系统影响

- **检视交互**：关联角色同屏时触发特殊对话 / 互动动画
- **战斗羁绊**：关联角色同时上阵获得「羁绊加成」
- **图鉴收集**：集齐一组关联角色解锁隐藏剧情 / 奖励

### 2.4 跨界事件 (LoreEvent)

定义卷入多个角色的「大事件」，是未来版本活动和内容扩展的基础结构：

- 触发条件：拥有特定角色 + 达到某阶段
- 奖励：新角色卡池、限定皮肤、隐藏剧情
- 每个大版本 = 一个跨界事件（运营节奏核心）

## 3. 角色养成系统

### 3.1 设计约束

1. **养成有可视变化** — 每次升级 / 升阶 / 加天赋，角色外观都有反馈
2. **满级 = 满天赋** — 满级时获得的天赋点恰好点满整棵天赋树（无互斥分支）
3. **终极突破** — 稀有终极角色可在满级满天赋后「突破」到最炫酷的终极形态

### 3.2 养成维度

| 养成行为 | 消耗 | 属性效果 | 可视变化 |
|---------|------|---------|---------|
| 升级 | 经验道具 / 金币 | 属性微增 | 光晕变亮、体型微增 |
| 升阶（阶段突破） | 阶段材料 + 碎片 | 属性上限提升、解锁新阶段 | **换装新阶段模型/皮肤、新特效** |
| 升星 | 角色碎片 | 星级提升、大幅属性增长 | 星级标识变化、气场颜色/强度变化 |
| 天赋加点 | 天赋点（来自升级/升阶） | 解锁/强化技能 | **对应分支视觉特效叠加** |
| **终极突破**（稀有角色专属） | 满级 + 满天赋 + 专属突破道具 | 突破等级上限、解锁终极技能 | **终极形态：最华丽专属外观** |

### 3.3 天赋树（背景驱动）

天赋树不是通用模板，而是 **每个角色根据背景故事定制**：

- 每个角色 2–3 个分支，每分支对应角色的一段背景 / 一种信念
- 分支命名、图标、描述都呼应背景
- 选择分支解锁对应「阶段皮肤」
- 天赋树可视化时显示角色关键背景插画

```
示例：角色「烬」（忍者次元叛逃者）
├── 分支 A「残烬之炎」— 灭族之夜的火 → 爆发/灼烧天赋
├── 分支 B「影忍之道」— 忍者训练的传承 → 闪避/暴击天赋
└── 分支 C「破誓者」  — 背叛忍道的代价 → 牺牲生命换力量天赋
```

### 3.4 天赋点总量设计

- 天赋树节点总数 = 角色从 1 级到满级获得的天赋点总量
- 天赋点来源：每级升级 + 升阶额外奖励
- 分支 **不互斥**，满级时整棵树全亮

### 3.5 天赋 → 视觉映射

每个天赋节点配置 `visualLayerId`，角色检视 / 战斗模型根据已点节点动态组合特效层：

- 分支 A「残烬之炎」→ 火焰粒子、橙红光边、披风燃火
- 分支 B「影忍之道」→ 暗紫色残影、刀光闪烁
- 分支 C「破誓者」  → 裂纹光纹、猩红气息
- **满天赋**：三色特效全开 → 触发「终极形态」

实现：通过 `Material Property Block` 动态叠加，避免 Draw Call 爆炸。

### 3.6 终极突破（稀有角色专属）

**触发条件**：满级 + 满天赋 + 专属突破道具。

**突破后变化**：
- 等级上限突破（如 60 → 80），继续属性成长
- **终极突破形态解锁**：全新独立模型，游戏中视觉天花板
  - 光翼 / 能量翼、多重光环、空间扭曲、粒子风暴、专属 shader
  - 独特待机动画、专属 BGM
- 解锁独一无二的终极技能

**终极形态视觉要素**（可选组合）：光翼、多重光环、空间特效、动态流光材质、粒子风暴、专属入场动画、检视全屏特效。

### 3.7 养成节奏示例（60 级满级）

| 等级节点 | 事件 | 天赋点 | 视觉变化 |
|---------|------|--------|---------|
| 1 | 初始 | 0 | 基础外观 |
| 10 | 一阶突破 | +3 | 第一阶段换装 |
| 20 | 二阶突破 | +5 | 第二阶段换装 + 气场 |
| 30 | 升星 ★→★★ | +2 | 星级光效 |
| 40 | 三阶突破 | +6 | 第三阶段换装 |
| 50 | 四阶突破 | +8 | 第四阶段换装 |
| 60 | 满级 + 天赋全满 | 补满 | **终极形态** |
| 60+（终极角色） | 终极突破 | — | **终极突破形态（最炫酷）** |

## 4. 抽卡系统

### 4.1 核心流程

```
玩家点击抽卡 → 检查货币 → 选择卡池 → 执行抽取算法 →
计算保底计数 → 产出结果(角色/皮肤/道具) → 抛「OnGachaResult」事件 →
触发次元裂缝演出 → 展示获得界面
```

### 4.2 抽取算法

- 先按稀有度概率抽取（如 SSR 3% / SR 15% / R 82%，可调）
- 再在稀有度内按角色权重抽取具体角色
- 保底：软保底（概率递增）+ 硬保底（N 抽必出）
- 大保底 / 小保底：首次 SSR 可能歪，下次 SSR 必 UP

### 4.3 卡池类型

- 常驻卡池
- UP 卡池（限定角色）
- 未来扩展：皮肤卡池、新手卡池

### 4.4 产出规则

- 抽到已拥有角色 → 转换为该角色碎片（用于升星）
- 抽到皮肤 → 加入收藏
- 抽到道具 → 加入背包

### 4.5 抽卡演出

采用「次元裂缝 / 传送门」风格：空间撕裂，角色从不同世界穿越而来。稀有度越高，演出越华丽（SSR 全屏特效 + 专属入场动画）。

## 5. 战斗系统（全自动放置）

### 5.1 核心循环

```
选关卡 → 编队伍(最多 5 个角色) → 开始战斗 →
自动演算(按速度/技能CD循环) → 胜负判定 → 发放奖励
```

### 5.2 自动战斗规则

- 角色按「速度」决定行动顺序
- 自动释放普攻 + 满足 CD 时自动放技能
- 技能有目标选择逻辑（最低血量 / 最高攻击等）
- 战斗可加速（2x / 3x）和跳过（已通关关卡）

### 5.3 羁绊加成（叙事联动）

- 队伍中有「战友」关系 → 攻击 +X%
- 「宿敌」同时在场 → 各自暴击 +Y%
- 集齐某事件相关角色 → 全队特殊增益

### 5.4 关卡设计（MVP）

- 线性 PVE 章节，每章多个关卡
- 关卡有推荐战力，不硬性卡关
- 通关奖励：金币、经验、升阶材料、碎片

## 6. 3D 检视系统

### 6.1 交互设计

- 单指拖动 → 360° 旋转
- 双指捏合 → 缩放
- 点击角色身体部位 → 触发反馈（动作 + 语音）
- 切换皮肤 / 阶段按钮 → 实时切换外观

### 6.2 交互反馈类型

- **部位点击反馈**：点击部位 → 角色转身展示 + 角色语音
- **动作展示**：播放标志性动作
- **语音**：按 `CharacterLore.personality` 播放对应风格语音
- **羁绊互动**：展示角色与已展示角色有关系 → 触发特殊双人互动

### 6.3 技术实现

- 自定义相机轨道（不依赖角色控制器移动）
- 模型通过 Addressables 动态加载
- 触摸输入用 Unity Input System 处理

## 7. 收藏 / 图鉴系统

- **角色图鉴**：已拥有 / 未拥有（未拥有显示剪影 + 背景故事预告）
- **皮肤图鉴**：按角色 / 世界分类
- **世界观图鉴**：已解锁的背景故事、跨界事件记录
- **关系图谱**：可视化角色关系网络（漫威 / DC 风格关系网）

## 8. 系统架构

### 8.1 分层架构

采用模块化分层架构，模块之间通过事件通信（解耦）：

```
┌─────────────────────────────────────────────────────┐
│                    Presentation 层                    │
│   UI │ 3D 检视 │ 抽卡演出 │ 动画/特效              │
├─────────────────────────────────────────────────────┤
│                    Domain 层（核心玩法）              │
│  抽卡系统 │ 角色养成 │ 战斗系统 │ 背包/收藏          │
├─────────────────────────────────────────────────────┤
│                    Data 层                           │
│  数据模型 │ ScriptableObject 内容 │ 存档持久化       │
├─────────────────────────────────────────────────────┤
│                    Infrastructure 层                 │
│  事件总线 │ 资源加载(Addressables) │ 音频/对象池      │
└─────────────────────────────────────────────────────┘
```

### 8.2 五个核心模块

1. **抽卡系统 (Gacha)** — 卡池配置、概率、保底、抽卡动画触发
2. **角色养成 (Progression)** — 等级、星级阶段、天赋分支、装备皮肤
3. **战斗系统 (Battle)** — 全自动放置战斗、队伍编排、伤害计算
4. **检视系统 (Inspection)** — 360° 自由旋转、缩放、交互反馈
5. **收藏 / 图鉴 (Collection)** — 皮肤、道具、图鉴、关系图谱

### 8.3 通信方式

模块间通过轻量 **EventBus**（C# event / ScriptableObject Event）通信。示例事件：

- `GachaResultEvent` — 抽卡获得物品
- `CharacterLevelUpEvent` — 角色升级
- `TalentUnlockedEvent` — 解锁天赋
- `CharacterBreakthroughEvent` — 终极角色突破

### 8.4 技术决策

| 方面 | 方案 |
|------|------|
| 内容配置 | ScriptableObject（策划可直接配置，无需改代码） |
| 资源加载 | Addressables（异步加载、包体可控、支持热更新） |
| 存档 | JSON 序列化 + `persistentDataPath`，带版本号 |
| 渲染 | Universal RP + 按世界切换 Renderer Features |
| 输入 | Unity Input System |
| 事件 | 自定义 EventBus |

### 8.5 性能目标（Android）

- 目标设备：中端安卓（骁龙 6 系 / 天玑 700 级别）
- 帧率：检视 60fps / 战斗 30fps
- 包体：首包 < 150MB
- 内存：峰值 < 1.5GB

## 9. 数据模型

### 9.1 核心 ScriptableObject

- **CharacterData** — 角色基础（ID、名字、世界、稀有度、基础属性、天赋树、检视配置）
- **CharacterLore** — 角色背景（出身故事、性格、人际关系、语音风格）
- **SkinData** — 皮肤（独立外观、可自由搭配、绑定世界画风）
- **TalentTree / TalentNode** — 天赋树（背景驱动、视觉层映射）
- **ItemData** — 道具（材料、货币、消耗品）
- **GachaPool** — 卡池（概率、保底、权重）
- **WorldData** — 世界（画风配置、渲染特性）
- **LoreEvent** — 跨界事件（触发条件、奖励、关联角色）
- **StageConfig** — 阶段配置（属性倍率、外观、解锁条件）

### 9.2 存档结构

- 拥有角色（阶段 / 等级 / 天赋点分配）
- 拥有皮肤、道具数量
- 抽卡次数（保底计数）
- 货币余额
- 预留 `userId`、`serverSyncStatus`（为联网迁移准备）

## 10. 扩展性设计（未来联网 / 社交 / 交易）

### 10.1 预留扩展点

| 未来功能 | 当前预留 |
|---------|---------|
| 排行榜 | 战力数值结构化，CollectionSystem 已统计收集度 |
| 玩家交流 | EventBus 解耦，未来加 ChatService + UI |
| 交易系统 | 物品已有唯一 ID 和所有权，未来加 TradeService |
| 版本活动 | LoreEvent 结构已定义，活动 = 限时卡池 + 事件任务 + 限定皮肤 |
| 服务器存档 | SaveSystem 预留 userId + 同步状态字段 |
| 热更新 | Addressables 已就位 |

### 10.2 联网演进路径

1. **当前（单机 v1）**：LocalSaveProvider + ScriptableObject 内容源
2. **过渡（弱联网 v1.5）**：RemoteSaveProvider 云存档 + 本地内容
3. **正式版（强联网 v2）**：服务器内容源 + 排行榜 / 聊天 / 交易 + 活动运营

Domain 层完全不感知数据来源，切换只在 Data 层完成。

## 13. 风险与待确认项

### 13.1 技术风险

- **混合渲染性能**：卡通 + 写实角色同屏，需在中端机实测 shader 和 Draw Call
- **终极形态特效量**：终极突破特效华丽但开销大，需做 LOD / 特效分级
- **Addressables 包体**：抽卡特效资源多，需做好资源分包和按需加载策略

### 13.2 待后续确认

- 首个世界的具体主题和 MVP 3–5 个角色的设定
- 抽卡具体概率数值和保底阈值（需数值策划）
- 赛季票和广告的具体植入方式（v1 可先不做，架构预留）
- 首个跨界事件的内容设计
