## StrategicBattleScreen

### 布局（战场区、角色槽、技能栏、回合指示、HP条…）

`StrategicBattleScreen` 是 **全屏可操作回合制战斗层**（2026-09-09），注释写明信息流：**敌方上排 → 战报 → 我方下排 → 技能条**（`StrategicBattleScreen.kt:49-52`）。整体结构：

1. **外层 `Box` + `PageBackground`**（`64-66`）：填满父容器（在 Tower 页上以 `if (showStrategic)` 条件盖层出现，见 Entry points）。
2. **顶栏 `Row`**（`68-89`）：
   - 标题 `"策略战斗 · 第 ${ui.floor} 层"`（`72-76`）
   - 回合指示 `"回合 ${ui.state?.turn ?: 1}"`，金色（`78-82`）
   - 右侧 `NeonButton("退出")` → `onExit`（`84-88`）
3. **`state == null` 时占位** `"准备中…"`（`91-97`）。
4. **敌方区**（`100-126`）：标签 `"敌方"`（Danger 红）+ 横向 `Row` 内多个 `UnitTile`，`weight(1f)` 等分。
5. **战报区**（`128-151`）：固定高 `96.dp` 的 `Box`，内部 `LazyColumn(reverseLayout = true)` 滚动 `ui.logLines`（已 `asReversed`），每行 11.sp、单行截断。
6. **我方区**（`153-176`）：标签 `"我方"`（Frost）+ 同样 `UnitTile` 横排；当前行动者用 `isActor = i == ui.currentActor`。
7. **技能条**（`180-236`）：仅当 `actor != null && actor.hp > 0 && !ui.finished` 时渲染：
   - 行动信息行：`"行动：{characterId 短名} · 能量 ${energy}/${maxEnergy}"`（`183-187`）
   - 技能按钮 `Row`：每技能一列，标签多行 `name + ⚡energyCost + CDn`（`189-227`）；`ready` 时可点，选中高亮 Gold，未 ready 半透明。
   - 底部 `GoldButton("确认行动")` → `vm.confirm()`（`229-235`）。

**`UnitTile`**（`248-326`）是单位卡片，含：

- 元素圆点 + `ElementTheme.glyph`（`285-293`）
- 角色短名（`characterId.substringAfterLast('_')`，`295-301`）
- **HP 条** `LinearProgressIndicator`：ratio 三段色 Success / Warning / Danger（`304-309`），下方文本 `hp/maxHp`（`310-315`）
- **能量条** 3.dp 高 Frost 色（`316-323`）
- 视觉态：阵亡黑底描边、`isActor` 金边金底、`selected` 元素 glow 边（`262-279`）

> 注意：这里 **没有立绘 / 镜头 / 3D 战场**，是纯色块 + 文本的战术板式 UI。

### 交互（选技能、目标、自动/加速、退出）

| 交互 | 行为 | 证据 |
|------|------|------|
| 选技能 | `clickable(enabled = ready) { vm.selectSkill(skill.skillId) }`；`skillReady` 校验能量与 CD | Screen `213`；VM `185-190` |
| 单体目标 | `SkillTarget.SINGLE_ENEMY` 点敌方 `UnitTile` → `vm.selectTarget(i)`；`SINGLE_ALLY` 点我方 | Screen `115-121`、`165-171`；VM `62-72` |
| 群攻/自身 | 选完技能 **立即 `confirm()`**，无需目标 | VM `73-74` |
| 确认 | `GoldButton` → `vm.confirm()`；单体需已选目标，能量/CD 不足直接 return | Screen `230-234`；VM `82-94` |
| 退出 | 顶栏 `NeonButton("退出")` → `onExit`；**无战斗中确认弹窗，直接退出** | Screen `84-88` |
| 自动 / 加速 | **不存在**。无 auto-battle、无倍速开关 | 全文件无相关标识 |
| 预选减摩擦 | 敌方回合结束后自动预选第一个 `energyCost == 0` 的技能（普攻），并默认第一个存活敌人 | VM `138-150` |

流程（VM 注释，`StrategicBattleViewModel.kt:32-36`）：`start → 玩家逐角色行动 → 敌方回合 → 下一回合 → VICTORY/DEFEAT → settleStrategicBattle 写盘发奖`。

### 动画/特效（伤害飘字、粒子、镜头）

**StrategicBattleScreen 本身几乎没有动画/特效**：

- 无 `DamageFloatingText` 接入（该组件仅被 `BattleResultOverlay` 调用，见下）。
- 无 `ParticleSystem` / `BattleHapticEffect` / 镜头 shake。
- 唯一动态感来自：
  - 战报文本追加（`logLines`，截断至最近 40 条，VM `103`、`130`）
  - 敌方回合前 `delay(350)` 的文本插入 `"—— 敌方回合 ——"`（VM `120-121`）
  - Compose 重组时 HP/能量条比例变化（无 animateFloat 过渡）
- 结算弹窗用现成 `GlassDialog` + `GoldButton`（Screen `354-356`），无自定义入场动画。

`ui/effects/` 下的战斗相关效果：

- **`HapticEffects.BattleHapticEffect`**（`HapticEffects.kt:107-138`）定义了 `CriticalHit / Victory / Defeat / LevelUp / Breakthrough / Error` 六类触觉（`146-153`），**但全仓库无任何 Screen 调用它**（grep `BattleHapticEffect` 仅命中定义与 KDoc）。
- **`ParticleSystem`**（`ParticleSystem.kt:87` 起）有若干封装（金箔/灰烬等），**战斗屏未引用**；`BattleResultOverlay` 内自带私有 `BattleParticles` Canvas，不依赖 `ParticleSystem`。
- `InkSplash` / `ParallaxScroll` / `MeshGradients` / `GpuEffects` / `DynamicTheme` 与战斗无关（InkSplash 用于 `DialogueScreen`）。

### ViewModel 状态机关键字段

`StrategicBattleUi`（`StrategicBattleViewModel.kt:19-30`）：

| 字段 | 含义 |
|------|------|
| `floor: Int` | 塔层 |
| `state: BattleState?` | 领域战斗状态（`playerTeam` / `enemyTeam` / `turn` / `phase` / `log`） |
| `currentActor: Int` | 当前行动我方下标 |
| `selectedSkillId: String?` | 已选技能 |
| `selectedTarget: Int?` | 已选目标下标 |
| `needTarget: Boolean` | 是否还需点目标 |
| `logLines: List<String>` | UI 文案战报（`takeLast(40)`） |
| `settling: Boolean` | 写盘结算中 |
| `outcome: TowerOutcome?` | 非空则弹 `StrategicResultDialog` |
| `finished: Boolean` | 战斗结束，隐藏技能条 |

关键私有状态与方法：

- `actedThisTurn: MutableSet<Int>`（`45`）：本回合已行动下标，`advanceActor` 找下一个未行动存活单位（`109-117`）；全员行动完 → 敌方回合协程（`119-154`）。
- `start(floor)`：`service.initializeStrategicBattle(floor)`，重置 UI（`47-56`）。
- `confirm()`：`service.executeStrategicAction` 产生新 `BattleState`，把增量 `log` 转 `strikeLabel` 文案（`96-106`）。
- 敌方回合后：`executeStrategicEnemyTurn` → `updateStrategicTurnState` → `checkStrategicBattleResult`；若 `VICTORY/DEFEAT/DRAW` 则 `settle()`（`122-136`）。
- `settle()`：`service.settleStrategicBattle(floor, victory, turn)` → 写 `outcome` + `finished=true`（`157-165`）。
- `dismiss()`：清空 outcome/finished/state（`167-169`）。
- `strikeLabel`：`【反应名】attacker → target  -damage 击倒！`（`177-181`）。

装配：`AppGraph.factory` 注册 `StrategicBattleViewModel(service)`（`AppGraph.kt:82`）；Screen 用 `viewModel(factory = AppGraph.factory)`（`StrategicBattleScreen.kt:59`）。

**服务层讽刺点**：`TowerService` 中全部策略战斗 API 被标 `@Deprecated("P2-11: 战略战斗UI零调用")`（`TowerService.kt:336,353,367,380,393,407,429`），但 `StrategicBattleViewModel` 实际在调用它们——deprecation 文案是 UI 接线前的旧审查结论，现已过期。

## Result overlay & replay

### 两套结算 UI（并存）

| 路径 | 触发 | 组件 |
|------|------|------|
| **自动模拟爬塔** `vm.challengeNext()` / `retryBest()` | `TowerOutcome.Completed` 非空 | `BattleResultOverlay` 全屏覆盖 + 页内 `TowerResultCard`（AnimatedVisibility） |
| **策略可操作战斗** `showStrategic` | `StrategicBattleUi.outcome` 非空 | `StrategicResultDialog`（私有，`GlassDialog` 轻量文案） |

两者都消费 `TowerOutcome`，但视觉规格差距极大。

### BattleResultOverlay（自动战斗全屏结算）

文件：`ui/components/BattleResultOverlay.kt`。

**分镜时序**（KDoc `56-64` + `LaunchedEffect` `92-101`）：

1. 背景遮罩淡入 200ms（`overlayAlpha`）
2. 结果标题 spring 弹入：胜利 `"✦ 攻克！"` / 失败 `"✖ 止步于此"`（`96`、`138`）
3. 内容淡入 300ms delay 100（回合数、奖励）
4. 按钮/提示淡入 250ms delay 200

**内容块**：

- `BattleParticles`（私有，`274-327`）：胜利 24 颗金箔下落 / 失败 12 颗灰烬上升，`infiniteTransition` 8s 循环 Canvas 圆点。
- **伤害飘字回放**：`log` 非空时叠 `DamageFloatingText(events=log, eventDelayMs=120, floatDurationMs=700)`（`121-130`）。
- 奖励卡：`RewardRow` 用 `animateIntAsState` 500ms 滚动计数（`166-210`、`245-249`）；`recordAdvanced` 时显示 `"纪录推进至第 N 层"`。
- **`BattleStatsPanel`**（`335-389`）：从 `List<StrikeEvent>` 实时算总伤害 / 克制次数（`damageMultiplier > 1.05`）/ 击杀 / 最高伤害 / 平均 / 攻击次数，2×3 网格展示。
- 底部 `"点击任意位置继续"`；整层 `clickable` → `onDismiss`（`111-115`、`225-230`）。

调用点：`TowerScreen.kt:266-279`，`onDismiss = { vm.dismissResult() }`，并传入 `completedResult.log`。

### TowerResultCard / BattleReportSection（页内结算卡）

`TowerScreen.kt:473-529`：胜利金渐变卡，标题、星尘/钻石/纪录文案，嵌套 `BattleReportSection`（`295-321`）可折叠战报（`heightIn(max=220.dp)` 内滚）。`StrikeRow`（`325-461`）按回合号 + 元素图标 + 攻击者→目标 + 伤害色阶（击杀红 / 克制金 / >200 橙 / >100 GoldHi）+ 克制徽标 + † 击杀标记。

测试：`TowerResultCardTest` 覆盖该卡（`app/src/test/java/com/milan/game/ui/tower/TowerResultCardTest.kt`）。

### DamageFloatingText

文件：`ui/components/DamageFloatingText.kt`。

- API：`DamageFloatingText(events, active, eventDelayMs=180, floatDurationMs=800)`（`40-46`）。
- 每条 `Animatable` 进度 0→1，`LaunchedEffect` 按间隔串行播放（`54-66`）。
- Canvas 绘制：从屏幕 45% 高度上飘 120px，水平由 `attackerId.hashCode()+turn+index` 伪随机偏移（`76-81`）；透明度前 20% 淡入后 40% 淡出（`83-88`）；缩放弹入 0.5→1.2→回落（`90-95`）。
- 颜色：击杀 `SealRed` + `" †"`，`damage>0` 一律当克制走金色（**简化逻辑，`98`**），0 伤害 `"MISS"`（`105-111`）。
- `drawDamageText`：`rememberTextMeasurer` + 描边层 + 填充层 + Shadow（`130-172`）。
- **`SingleDamageFloat`**（`178-223`）单条即时飘字，**无调用方**。

### BattleReplay（疑似死代码）

- 功能：逐步播放 `StrikeEvent` 日志，维护我方/敌方 HP Map，进度条，`StrikeEventBubble` 显示克制/击杀标签，播放/暂停/跳过按钮（`69-304`）。

## Entry points

战斗 **没有独立 NavRoute**。`Routes.kt` / `MilanNavHost` 中无 `BattleRoute`（仅 `BattlePassRoute` 纪行，无关）。

### 唯一入口：无尽之塔 TowerScreen

```
Home → onOpenTower → navigate(TowerRoute) → TowerScreen
```

- 路由：`MilanNavHost.kt:252-256` `composable<TowerRoute> { TowerScreen(...) }`
- 主页入口回调：`MilanNavHost.kt:170` `onOpenTower = { navController.navigate(TowerRoute) }`

TowerScreen 内两种开打方式（`TowerScreen.kt`）：

1. **自动模拟**（主 CTA）：`GoldButton("⚔ 挑战第 N 层")` → `vm.challengeNext()`（`187-196`）；战票不足禁用。服务层纯模拟后写 `result: TowerOutcome`，弹 `BattleResultOverlay`（`266-279`）。
2. **策略可操作**：`NeonButton("策略挑战第 N 层（可操作）")` → `showStrategic = true`（`200-205`）→ 条件渲染 `StrategicBattleScreen(floor=nextFloor, onExit={ showStrategic=false })`（`281-287`）。**不经过 Navigation，是同屏覆盖层。**

另有复刷：`NeonButton("复刷第 best 层")` → `vm.retryBest()`（`208-216`）。

空编队引导：`EmptyState` → `onOpenDeck`（`163-170`）。

### 其他模式：无战斗 UI

| 模块 | 是否有战斗 UI | 说明 |
|------|----------------|------|
| **Arena** `ArenaScreen` | **无** | `OpponentCard` 点「挑战」→ `vm.challenge(opponent)` 服务层静默结算（`ArenaScreen.kt:219-223`；`ArenaViewModel.kt:75-76`）。无 HP、无战报、无 overlay。 |
| **Story** `DialogueScreen` | **无战斗** | 剧情对话 + `InkSplashTransition`，非战斗玩法。 |

## Open gaps

1. **策略战斗视觉极简**：无伤害飘字、无受击动画、无元素反应特效、无角色立绘；战报是文本行。已写好的 `DamageFloatingText` / `BattleParticles` 思路只接到了自动战斗结算 overlay，**未回灌到进行中的 StrategicBattleScreen**。
2. **`BattleReplay` 死代码**：完整回放组件（HP 同步、播放控制）零引用；且「跳过」按钮无点击处理。
3. **`BattleHapticEffect` / `SingleDamageFloat` 死代码**：触觉战斗事件体系已定义，战斗胜利/失败/暴击均未触发触觉。
4. **两套结算 UX 不一致**：自动塔 = 全屏 overlay + 粒子 + 飘字 + 统计；策略战 = 小 `GlassDialog` 纯文案。玩家感知像两个游戏。
5. **无自动/加速/二倍速**：策略战必须逐角色点选；敌方回合仅 350ms 固定 pause。
6. **退出无确认**：进行中点「退出」直接 `onExit`，不结算也不返还明确提示（战票是否已扣取决于 `settleStrategicBattle` 是否已跑——进行中退出不会 settle，门票语义需对照 `challenge` 路径；策略入口本身不走 `vm.challengeNext`，门票在 `settleStrategicBattle` 才校验扣除，中途退出可能 **未扣票也未发奖**，属预期但未在 UI 提示）。
7. **`@Deprecated("战略战斗UI零调用")` 文案过期**：`TowerService` 策略 API 已被 VM 使用，易误导后续重构删 API。
8. **敌方 ID 约定泄漏到 UI**：`BattleReplay` / `TowerScreen.unitLabel` 硬编码 `tower_f` 前缀。
9. **`DamageFloatingText` 的「克制」判定退化为 `damage > 0`**（`98`），与 `BattleReplay` / `StrikeRow` 的 `ElementChart.damageMultiplier > 1.05` 口径不一致。
10. **Arena 战斗无过程 UI**：静默挑战，结果无战报无 overlay，与塔体验割裂。
11. **Compose UI 测试缺口**：`StrategicBattleScreen`、`BattleResultOverlay`、`DamageFloatingText` 均无渲染测试。
12. **无独立 Battle Route**：无法从深层返回栈进入战斗；策略战是 Tower 内 boolean 覆盖层，进程死亡恢复会丢 `showStrategic`（非 rememberSaveable）。
